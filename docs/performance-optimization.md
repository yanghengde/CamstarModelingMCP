# 性能优化进度

更新日期：2026-11-07。

## 第一批：减少重复输入和阻塞读取

- LangGraph 与 legacy 推理路径仅去掉已完整存在于首条 system 消息中的相同规则。用户和工具消息不能触发规则删除；旧检查点缺失规则时仍补充完整规则。未截断历史，也未删除任何审批或业务约束。
- Excel/CSV 导入预览最多读取 201 行，第 201 行用于拒绝超过既有 200 行上限的文件，拒绝前不查询 MES。解析放在线程中执行。
- Excel 结构预览每张表读取最多 201 行，保留前三行样例，使用上下文管理器关闭工作簿。`row_count_is_lower_bound=true` 表示行数是下限，不能当作精确总行数。
- 上传端点使用 FastAPI 同步端点线程池执行复制。聊天状态及事件订阅的入口查询同样移到线程池；SSE 每次轮询通过 `asyncio.to_thread` 在单个连接中读取状态和最多 200 条事件。
- 为会话最近任务查询增加 `(username, session_id, started_at DESC)` 索引，应用初始化时自动建立。

## 本地测量

默认系统提示词下，LangGraph 每轮附加指令减少 **3,711 字符**，系统规则总字符数减少 **12.24%**。这是确定的文本体积变化，不是 token 或真实推理时延降幅。所有原有规则内容保留。

合成 10,000 行、4 列 XLSX 文件，分别执行三次 `pd.read_excel`，本机耗时中位数：

| 读取方式 | 返回行数 | 中位耗时 |
| --- | ---: | ---: |
| 原完整读取 | 10,000 | 1,565.89 ms |
| `nrows=201` | 201 | 351.86 ms |

此样本解析耗时减少约 77.5%，约快 4.45 倍；不代表完整导入流程提速。Excel 引擎仍需打开工作簿、读取元数据/共享字符串，因此行数上限不等于整个附件的硬性内存上限。

## 第二批：运行基线、上下文与存储预算

### 运行追踪与排队

后台任务创建时分配 `run_id`，通过 ContextVar 传递到推理、工具及线程内日志。同一提示词的多次提交分别统计。`Run_Total` 从创建任务记录到终态落盘，包含排队、状态写入及执行；不包含浏览器网络、HTTP 请求解析和会话身份准备时间，也不累计人工等待审批的时间。每次确认恢复是新的 run。

日志提供 `queue_seconds`、`execution_seconds`、`event_loop_lag_p95_ms`、`event_loop_lag_max_ms`。每 100 ms 采样一次事件循环延迟，P95 使用最近最多 1,024 个样本，max 覆盖本 run 全部采样；短任务未取得样本时返回 null。日志页面展示这些指标，任务总耗时不再与内部推理/工具耗时重复相加。

任务队列按全局和用户设置运行/等待上限。超过接纳容量返回 HTTP 429 和 Retry-After；等待超时不会执行工具。同一会话仍只能有一个活动任务。调度跳过已占满个人执行配额的用户，使其他用户可以使用空闲槽位。相同 request_id 的精确重试优先返回原任务，即使队列已满也不会生成第二次执行。

HTTP 创建、取消、状态写入、会话保存与经验库访问移到受控线程。取消时等待已开始的磁盘事务完成；断开的 POST 不会留下已提交却无人接管的 queued 记录。SSE 改为日志提交后通知订阅者，空闲时只等待通知和 15 秒心跳，不再每 250 ms 查询数据库。仍支持单 Uvicorn worker。

### 领域规则与历史预算

原业务段落按所选工具领域加载，通用发现、参数和审批约束始终保留。省略式追问沿用已有工具路由结果，加载工具组后的规则会随领域扩展。

预算采用本地 cl100k_base BPE 加消息开销估算 token，供不同模型共用；不是供应商返回的精确 token 数。服务启动时检查分词器和编码缓存，缺失时明确拒绝启动，避免悄悄退回按字节计数。预算只覆盖消息历史，系统规则和工具 schema 另外记录。保留全部用户消息、全部工具调用/结果、最近两轮，以及包含计划、对象或审批标识的旧助手文本。只省略较早的非关键说明，原会话和检查点不修改。必需证据仍超限时，返回 limited 并在下一次模型推理前停止；用户需明确对象/计划在新对话继续，不能通过丢弃证据来绕过预算。

修改待确认参数时显式标记旧审批已撤销，提示模型为新计划提出受审批门保护的调用，避免普通文本确认和系统确认重复。

### 索引、惰性加载与保留策略

- 性能 JSONL 保持可导出；旁路 SQLite 按新增字节增量建索引，使用序号快照和键集游标分页。翻页只取所选组及其步骤，避免每页重建全部分组。首次索引仍需读取历史文件。
- 每个会话维护小型摘要。重启和列表读取摘要，需要正文时才加载；旧文件首次启动建立摘要。写入采用临时文件加原子替换，摘要失效时重新从正文生成。已加载正文当前仍保留在进程内，没有实现 LRU 淘汰。
- 上传默认限制单文件 20 MiB；接收层也约束 chunked 请求，另允许最多 64 KiB multipart 包装开销。解析最多 20 张工作表，直接传入导入工具的文件同样检查大小和表数。
- 每日后台维护：性能组默认保留 90 天，聊天事件默认 30 天，上传默认 7 天；设为 0 可停用对应清理。性能组按完整组过期，活动/无终态 run 保留。聊天仅清理 completed/cancelled/failed 的过期事件，保留请求身份记录、待审批及未完成恢复证据。
- 上传清理仅作用于 uploads 目录中系统生成名称的普通文件；待审批或未完成 run 引用的文件保留。经验库只清理过期成功遥测，候选和已审核经验保留。会话正文、业务计划和 LangGraph 检查点不自动删除。
- 日志整理会使旧分页游标过期，API 返回重新加载提示。SQLite 索引为可重建数据；业务计划/会话没有数据库迁移或破坏性重建。
