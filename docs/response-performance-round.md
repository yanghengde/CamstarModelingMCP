# 回复性能优化与验证

截图对应日志的任务总耗时约17.21秒，排队约0.005秒；模型相关阶段约17.13秒，其中首个正文/工具事件约8.20秒。不能把这些时间归因为前端渲染或排队。

## 本轮变更

- 通用能力简介直接呈现本次实际目录，列出全部非空分组、当前受限状态和可展开的具体限制。每次重新读取目录，无生成答案缓存。详细参数、领域限定和复杂问题仍走原模型链路，保持思考模式及自动工具选择兼容。
- 即使不启用历史token上限，默认也给模型提供旧能力目录的精简视图。完整原响应继续保留在会话/检查点；用户指令、业务工具响应、计划/摘要/未知状态不删除。仅目录索引允许按需重新读取详情。
- 对相同消息文本复用token估算结果，缓存有上限，内容改变即重新计算。
- 工单关联容器按最多4个并发只读任务补充状态/历史；每个容器先核对工单身份，再读其历史；输出顺序、分页、关闭/零数量容器和未知字段语义保持。写入流程没有改成并发执行。
- 日志增加请求准备、首个模型事件、首个正文/工具事件、模型响应耗时；本地能力预读单独计为工具调用，直接呈现计为独立阶段。只记录思考/正文字符数量，不额外记录思考正文。
- 修复验证中多次遇到的Windows本地会话文件被短暂占用问题：仅原子替换本地文件时短暂重试，最多等待约0.1秒；持续失败仍报错、原文件保持。与MES事务提交无关。

## 配置与生效

```ini
AGENT_CAPABILITY_FAST_REPLY=true
AGENT_PROJECT_DISCOVERY=true
READ_QUERY_CONCURRENCY=4
```

并发可调为1恢复串行。要在history budget为0时恢复完整目录输入，设置AGENT_PROJECT_DISCOVERY=false。已有预算上限的保护逻辑保持。

后端代码/配置需重启服务后加载；日志页面刷新即可读取新的展示逻辑。本轮没有自动重启用户运行中的服务。
