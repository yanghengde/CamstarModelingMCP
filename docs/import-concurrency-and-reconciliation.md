# 导入并发保护与只读核对

本轮增加以下能力，未执行业务写入。

- `execute_workflow_import_plan` 在领取计划前取得所有目标 Workflow 名称/版本的操作系统文件锁。锁按稳定顺序取得，名称与版本规范化后散列，避免锁文件名泄漏对象名称。同一路线冲突立即返回，未领取计划；不相关路线可独立执行。锁随句柄关闭释放，进程退出也由操作系统释放。
- 计划绑定创建时的 Modeling 服务地址指纹，并纳入摘要。执行和现场核对均拒绝不同服务环境；旧版没有环境指纹的计划需重新预览，不能直接迁移到新环境执行。服务地址相同但底层数据库切换无法仅凭此指纹识别，不能当成数据库身份认证。
- 保留整批写入前的预检，再在每条 Workflow 开始写入前重新读取并比较现场。发现变化停止后续写入，之前已完成的动作保留日志。
- 新增只读 `reconcile_workflow_import_plan`。比较现有步骤顺序和 Spec 引用与计划目标，或比较预览前的原结构；分别报告目标路线匹配、原状态匹配、差异、未知。仅目标步骤/Spec 匹配不意味着所有配置完全一致，也不能证明变更由哪一次请求完成。

核对不会释放其他任务的锁、修改计划状态、重新批准、自动续跑或回滚。进程中断后，原计划仍不可自动重放；应核对现场，再针对当前状态重新预览。

限制：互斥保护只覆盖共享同一个锁目录且使用本执行入口的进程；不覆盖 Designer、其他服务器部署或直接维护接口。预检与写入之间仍有外部并发窗口；未宣称跨请求原子事务、全局锁或已解决所有并发修改问题。OS 锁释放也不能证明远端正在处理的请求已停止。

验证：130 项相关测试、2 项子测试通过，含跨进程锁竞争、异常后释放、不同路线不互斥、环境切换前置拒绝、第二次预检变化拦截、核对不写入且不重置计划。尚未在业务库执行真实导入；相关受控验收仍需要测试环境。

重启服务后生效。升级前生成的旧计划需重新预览。
