# C6：无控制限的原始参数走势图

2026-11-12，Asia/Shanghai。继续“不依赖现场引擎”的开发范围，新增只读入口`get_spc_parameter_trend`，补齐“指定参数查原始历史→核对来源→聊天异步出图”。它是原始数据展示，不是新的SPC判异算法。已有I-MR/Xbar-R及p/np/c/u控制图保持原门禁。

## 如何使用

可以问：“把容器C的Diameter参数历史画成原始走势图，不做SPC判异。”

Agent先调用`get_container_collection_history(container_name="C", parameter_name="Diameter", limit=100)`。新增的`parameter_name`为精确匹配，单引号按SQL字符串转义，返回内容再次核对参数名；同时返回原始`TxnDateGMT`。分页依旧不是一致快照，`page_complete`不代表该参数全部历史完整，也不证明某次提交成功。

再将明确选定的`DataPointHistoryDetailId`按原始GMT严格先后传给`get_spc_parameter_trend(history_ids=[...])`，最多100点。默认`scope_kind="container"`，只读同一容器；用户明确要同一过程的跨容器走势时才使用`scope_kind="process"`。不为凑连续区间跨容器、跨参数或换单位补点。

没有独立基线、没有有效控制限或没有现场SPC引擎，仍可展示该趋势。仅有一个合法观测也能显示点符号。横轴按观测先后**等距排列**，标签保留原始GMT，时间精度不转换为JavaScript毫秒；它不表示采样时间间隔相等，悬停及原始数据表保留完整时间和值。

## 来源核实与限制

复用SPC历史读取的原始点、父采集历史及主事务三层身份核对，要求直接数值、未冲销，同一定义版本、参数、单位、产品、Operation、Spec、工艺步骤、工厂及设备。容器模式额外绑定ContainerId并在完整区间查询中限制容器，避免其他容器的同过程记录被拼入。过程模式仍完整核对同一生产范围内首末点之间的所有记录。

点的GMT顺序须严格明确，重复时间、遗漏、重复或超过上限均不绘制，不自行删点、换算或猜顺序。复读原始区间、注释及单位定义，读取期间的变化会使本次结果失效。返回源历史、范围模式、原始ID、原值、GMT、单位和摘要，图表适配器再次核对逐点输出与摘要绑定的来源一致。

趋势图保留有未冲销排除记录的原始点，以灰色菱形标记，不悄悄删除；“存在未冲销排除记录”不等于已确认当前排除/恢复状态。注释读取缺失、孤立或变化时仍拒绝绘图。原有SPC判异入口继续拒绝含有效排除记录的区间，没有因趋势展示而放宽。

输出明确`analysis_performed=false`、`control_limits=null`、`native_spc_result=false`、`ready_for_mes_write=false`及`release_authorized=false`。趋势没有CL/UCL/LCL、红色判异点或合格/放行结论，不能据此准备原生违例报告。若明确要求SPC判异，仍需独立基线或版本化控制配置，并调用原分析入口。

## 页面与性能

复用[问答异步出图](chat-charts.md)的快照、SSE描述符、可见区域加载、Worker绘图与PNG转换、180毫秒交互安静期、流式文字优先和离屏释放。ECharts继续只在Worker运行，图表快照和图片不额外写入模型上下文；模型保留原始工具结果用于回答与溯源。原始数据表分页展示GMT、原始ID、原值和记录说明，不为趋势添加控制限列；支持SVG导出。

浏览器检查新增100点趋势、七位小数GMT、排除记录图例、原始数据表、无控制限SVG和单点图。原有100张历史图、每图两个500点面板的输入/滚动压力检查继续保留。前端模板另通过实际ECharts SVG核对单点符号和趋势不带判异/控制限系列。
