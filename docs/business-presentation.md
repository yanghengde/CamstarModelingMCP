# 业务结果与技术详情的呈现

更新：2026-11-07。

## 默认交付方式

面向制造业务人员，先回答查到了什么、结果是否完整，以及确有必要的下一步。单对象优先显示名称、描述、实际适用的版本与业务状态；列表保留分页范围。用户明确要求技术诊断、原始字段或完整数据时按要求展开，复杂任务不机械限制篇幅。

常规回复省略内部 ID、接口方法、JSON 校验标志、无意义的“无 Status/无版本”、排查方法清单和重复免责声明。示例配置不能用于正式检验、未取得明细、数量/库存影响、删除/关闭、签名要求及提交结果未知等决策信息必须保留。“未冻结”不等于启用、可执行或已验收；读取校验错误不等于已确认配置缺陷。

## 界面行为

- 有工具调用的助手文字归入默认折叠的处理详情。历史加载、新任务实时输出和刷新后的事件回放采用同一规则；兼容旧事件日志。
- 最终业务回答仍正常展示和流式渲染。旧版本已保存的长篇最终回答不自动重写，避免改动审计历史。
- 系统异常拆成简短业务提示和可展开的技术详情。技术信息按纯文本呈现，限制长度并脱敏；原始异常仍供诊断，已经提交的操作需先核实。
- 工具失败详情写入 tool_diagnostic 事件，出现在处理详情中，不当作独立聊天答案。仅记录错误，不在事件中重复存放整份成功业务数据。
- 连接状态显示“服务已连接”，处理终态显示“处理已结束”，不将执行引擎名称或任务结束等同于业务事务已验证成功。

## 执行与安全

同一用户请求中，相同工具、相同参数的失败只读查询不重复执行；更换明确参数或用户在新一轮要求重新核实仍允许读取。该保护不自动重发、重排或替代写入工具。

原始业务消息、工具结果、计划编号/摘要、对象身份及检查点保持完整，呈现优化不改变审批门、签名和事务结果核验。没有工具证实的替代路径时，不要求用户提供明细编号或重建表来绕过读取失败；当前站点/数量回读也不能单独证明一次未知写入已经成功。

## 实现入口

- `agent/prompts.py`：业务呈现规则及模型请求末尾的交付检查，旧会话同样应用。
- `agent/langgraph_runtime.py` / `agent/llm_client.py`：区分过程与回答、发送工具诊断；两个执行引擎保持一致。
- `core/user_errors.py`：业务异常消息与脱敏诊断。
- `agent/read_efficiency.py`：请求内重复失败读取保护。
- `static/workspace.js` / `workspace.css`：折叠详情、历史与回放一致性。
