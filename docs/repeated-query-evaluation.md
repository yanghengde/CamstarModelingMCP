# 多轮路由与重复查询评估

新增 `scripts/evaluate_queries.py`，默认只运行离线路由检查。现场只读查询和供应商模型调用分别由 `--live`、`--llm` 开启。不会执行模型返回的工具调用，更不会写入业务数据。

```powershell
venv/Scripts/python.exe scripts/evaluate_queries.py
venv/Scripts/python.exe scripts/evaluate_queries.py --live --llm --rounds 3
venv/Scripts/python.exe -m pytest tests/test_query_evaluation.py -q
```

默认报告为 `docs/query-evaluation.json`，可以用 `--output` 指定另一个文件保存历史结果。每个样本后落盘；失败样本保留，参与耗时统计。路由、查询或模型严格检查任一失败时命令返回非零，便于接入回归任务。`--llm` 会产生模型费用。

## 本轮修复

原路由只保留最近三个用户问题，且把“当前状态”“再查历史”当作新的查询主题，导致连续追问丢失容器领域。现在跳过这些泛化追问，回溯最近明确领域；明确 SQL/Query 切换仍保留，历史写入意图不会自动继承到本轮。路由提示同时明确最新问题优先，历史只用于补全上下文。

新增四类回放：连续五轮省略追问、从产品写入切换到工单查询、容器切换到产品工艺链、工单切换到容器返工历史。离线验证目标工具可见、无旧领域泄漏、无写工具。模拟助手仅提供轮次结束标记，不伪造业务数据或工具结果，因此这是意图回放，不是完整端到端对话验收。

## 测量口径

- 服务查询：容器状态、六段关联追溯、产品工艺链、工单当前页，每类三轮，每轮新建连接和复用连接各一次。
- 新建连接仅关闭本地 HTTP 连接池，不能清空服务器、数据库、操作系统或模型缓存。报告不能称为严格冷/热缓存实验。
- 模型按需/全量候选交替先后顺序，记录供应商原始 usage 和缓存 token（未返回则为 null）；耗时与服务查询分开统计。
- 严格模型成功要求仅选择预期工具、参数是合法 JSON 对象、输出未截断。额外读取或发现调用也计为严格失败；失败不等于业务查询一定错误。当前未验证所有参数的业务正确性。
- 追溯分段和工单当前页成功不代表全历史或全工单读取完整。保留 `complete`、`page` 等范围标记。
- 中位数和最近秩 P95 包含失败耗时，每组仅三次，P95 只是样本描述，不能代表生产 SLA。

## 尚未关闭的验收项

2026-10-22 本轮结果见 `query-evaluation.json`：四类离线路由全部通过；24 次服务查询范围内检查通过。按需候选严格通过 11/12，全量候选严格通过 9/12，均命中预期工具；未通过项均为历史追问时额外查询当前状态，故评估命令返回 1。不能将其称为全部通过。

按需输入 token 为 1,995–4,379，全量为 22,280–22,309。保留了缓存 usage，不能据此推算等比例费用或延迟收益。相关自动化回归 143 项测试及 2 项子测试通过。路由代码需要重启服务才生效，本轮未重启服务。

真实非空拆分、合并、返工和工单生产前后置流程样本，测试环境真实导入及中断恢复，完成数量与挂起状态业务口径，外部 MCP 授权和跨系统并发修改仍需单独完成。此评估不会将这些事项标记为已验收，也不自动安排定时任务或重启服务。
