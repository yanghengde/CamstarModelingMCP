# 能力目录即时刷新

能力介绍隐藏停留时间、处理时长和历史盘点/核查日期。原始核查证据与运行日志保留，普通介绍不再复述日期免责声明。聊天处理卡片仅显示运行状态，页面重新打开历史运行也不附加秒数。

## 已实现的刷新路径

1. 本地 LangGraph/legacy 收到新的能力介绍问题时，首次模型调用明确要求调用 get_capabilities。上一轮曾查询过目录不算本轮已刷新；本轮取得结果后恢复正常推理，避免每轮强制重复查询。
2. get_capabilities 每次读取当前进程的实际 MCP 注册表与最新 core-capability-gaps.json；工具增删、已保存的能力资料修改在下一次目录调用时反映。文件损坏/不可读时说明资料不可用，不回退旧副本。
3. 工具目录同时比较 agent/tools/core 的当前源码与进程启动时的源码摘要。发生修改、增加或删除时返回 freshness.reload_required=true；直接相关缺口项显示“实现变更待加载与复核”，不把磁盘新代码当作已经运行。
4. 外部 MCP 初始化说明和工具说明也要求每次介绍能力重新读取目录。外部客户端是否实际调用仍由客户端决定；更新初始化说明后需要重启服务并重新连接客户端。

## 更新方式与边界

| 变更 | 生效方式 |
|---|---|
| 当前进程内注册表变化 | 下一次目录调用直接读取 |
| 已保存的支持范围、限制和验收说明 | 下一次目录调用重新读取资料，无目录结果缓存 |
| 新增/修改 Python 工具实现 | 部署完成后重启服务加载；运行中的旧进程会提示待重新加载 |
| MES 权限、配置或服务端契约变化 | 目录调用不执行现场事务，不能自动证明可用；实际执行仍经原生校验 |
| 新的现场验收通过 | 依据真实结果更新对应能力资料；注册工具或源码存在不能自动提升为已验收 |

源文件摘要检测仅说明运行进程与磁盘是否一致，不能证明验收证据与全部依赖仍一致。资料中的支持结论仍需随实际验收维护；本次没有加入自动验收、自动热重载或后台探测 MES。

相关验证：tests/test_capability_refresh.py 覆盖新问题强制刷新、单轮不重复、最新资料、运行注册表变化、源码修改/删除，以及本地模型调用参数。原能力目录与上下文预算测试继续核对全部分组和限制保留。页面呈现由 tests/workspace_presentation.test.cjs 验证。
