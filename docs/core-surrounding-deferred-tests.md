# 核心周边能力集中验收清单（持续维护）

用户约定：先推进不依赖现场写入的开发，T00–T09 后集中补测。这里先记录遗漏内容，开发结束后补齐成可执行测试方案。不得将模拟测试通过当作现场事务验收通过。

| 阶段 | 待准备数据 | 待验证内容与预期证据 |
|---|---|---|
| T00 | 已归档契约对应的当前服务版本 | 核对契约未漂移，更新字段/接口证据 |
| T01 | 非空设备、资源组、工序关联 | 多级组/循环/分页/缺失资源；聊天端准确展示来源与不完整项 |
| T02 | 标准BOM、订单BOM、两个明确版本 | 用料关联、行增删改、空与缺失区别；原始记录与差异对照 |
| T03 | 非空用户采集和分组定义、TxnMap | 类型、必填、枚举、单位、表达式限值、动态要求；逐点对照客户端 |
| T04 | 完整工单→产品→工艺→资源/BOM/采集配置 | 缺项与完整配置各一组；未知项不被报告为已就绪 |
| T05 | 有需求的测试容器及序列/批次/库存来源 | LoadRequirements、实际量与累计量、来源余额、重复/超时/部分失败、可追溯历史；执行链尚需开发补齐 |
| T06 | 当前工序明确且有CollectData映射的测试容器、定义版本和授权测试值 | 见下文；成功事务关联与未知结果恢复尚需开发补齐 |
| T07–T09 | 随后开发时补充 | 每阶段结束时追加，集中验收前不得留空 |

## T06：后续现场步骤

1. 记录容器ID、当前工序/路线步骤、采集定义ID/版本、采集点ID/类型、单位、限值、必填、动态枚举及覆盖规则。明确允许测试的具体数值，不使用生产实测值的替代数据。
2. 对合法数值、0、负值、小数、字符串、缺项、未知点、类型错误分别预览；核对字段映射及服务回显。布尔/日期/对象/分组目前应明确不支持。
3. 确认界面必须显示容器、定义、点名和值；未确认不能写。预览到执行之间改变工序、定义或约束，应拒绝旧计划。确认服务仍执行当前现场规则。
4. 在明确授权下提交一次合法值，保存原始响应、业务错误/完成信息和历史。确定可用于准确关联本次事务的标识，完成成功状态判定后才能报告 verified_success=true。
5. 对上下限边界和越限值验证现场行为：拒绝、记录异常、允许覆盖分别以实际配置为准；工具不得擅自设置覆盖标记。
6. 同一计划并发/重复调用只发送一次；超时、连接中断、空响应、部分失败保持 unknown/in_flight，不能通过另一计划重复写。
7. 对存在历史但响应丢失、没有可匹配历史、历史查询失败分别验证核实流程；核实后解除锁定必须有明确证据，不能把空页当作失败证据。
8. 检查当前只读历史查询的非空关联、分页、容器隔离、事务筛选、原始数值及限值标记。现有历史表的全部明细计数为0，尚无非空验证。
9. 验收证据按案例保存：准备数据、操作、预期、实际响应、历史对照、是否通过、遗留缺陷。测试数据清理方式需遵守现场规则，不自动删历史。
