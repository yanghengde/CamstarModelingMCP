# 问答出图与聊天响应

2026-11-12：新增问答图表基础设施。用户要求出图、控制图、趋势或SPC分析时，后端从支持的只读工具结果生成固定图表快照。普通文字查询不生成图表，也不加载ECharts。图表展示可以延后，聊天文字优先。

## 当前范围

| 来源工具 | 图表 | 口径 |
| --- | --- | --- |
| `get_spc_parameter_trend` | 原始参数走势图 | 同一容器或明确的同一过程范围，无控制限、不判异 |
| `analyze_spc_series` | I-MR、Xbar-R | 明确输入数据，本地统计计算 |
| `analyze_spc_history` | I-MR、Xbar-R | 已核对来源与完整区间的MES历史，本地统计计算 |
| `analyze_spc_attributes` | p、np、c、u | 明确计数与检查单位，本地三西格玛近似 |
| `get_mfgorder_progress` | 工序容器分布柱状图 | 明确当前页或完整关联列表；容器数不等于产量 |

图表沿用工具返回的统计量、控制限、原始点ID和判异标记。浏览器只为绘图转换数值，原始十进制字符串仍用于查看与悬停，不重新计算判异。p/u可显示逐点变化的控制限。基线不混入评估段；MR不跨基线边界补点。没有接入现场SPC引擎，不能把本地图当原生引擎计算、合格证明或放行依据，也不等于已覆盖Camstar所有图型。

原始参数走势无需基线/控制配置，最多100个经过源核实的点，灰色标记仅代表存在未冲销排除记录，不是判异。完整GMT保留到七位小数，按观测顺序等距展示；原始数据表不附控制限列。详情见[C6参数走势](c6-parameter-trend.md)。

单面板最多500点、每图最多两个面板、快照最多512 KiB；超过范围保留文字结果，不截断序列后声称完成分析。MES历史分析工具自身更严格的100点限制继续有效。当前不接收模型自拟数据、HTML、ECharts options、URL、formatter或代码，其他统计工具需要逐项接入适配器，不能声称所有统计问答已能出图。

## 聊天优先的实现

- ECharts 6.0.0固定版本从本机提供，仅在独立Web Worker中按需加载、排版及绘制。Worker用OffscreenCanvas生成PNG供页面显示，另存SVG用于导出；聊天主线程不执行ECharts。每次实例和画布绘制后释放，无动画。浏览器不支持OffscreenCanvas时保留文字、原始数据和SVG导出，不退回主线程绘图。
- SSE只传递快照ID和标题；进入视区才读取快照。最多保留两个可见图的负载和图像，离屏取消请求、释放图像URL与数据。已知占位高度保留，避免释放时跳动。
- Worker串行绘制；主线程在空闲时调度，PNG使用异步解码的`img`显示，不向聊天DOM插入大量SVG点。流式文字输出期间取消未完成快照请求、暂停新加载、新绘图及图像挂载，已显示的图不反复重建。没有直接使用SVG作为显示图片：降速检查发现SVG图片本身也可能带来主线程解析/绘制长任务，因此将这一步移到Worker。
- 输入、点击、触摸和滚动后至少等待180毫秒安静期，并检查待处理输入，才开始可选的JSON解析、后台绘图调度和图片挂载；解码完成后再次检查。用户持续操作时允许图表继续等待。调度、释放和缩放更新只遍历最多两个可见图卡。输入框在支持的浏览器采用原生内容自适应高度，避免每次按键强制重排整段历史。
- 原始数据表按需展开，每页30行。范围选择为全部、最近100点、最近50点；不改变原始快照。支持SVG导出并保留数据摘要、来源及限制说明。
- 切换会话使旧回调失效、取消旧请求、终止Worker。Worker、网络或快照失败仅显示图表提示，文字历史和输入仍可使用。历史长列表分批恢复。
- 图表存储/构建在线程中执行，可选发布及历史图表索引最多等待200毫秒，不占用服务端异步事件循环；超时放弃当前图表事件，保留业务工具结果。慢磁盘后台完成的快照可在之后重新打开历史时恢复。
- 页面请求历史时使用`presentation=true`：在服务端线程中移除不展示的工具原始JSON、调用参数和系统提示词，仅传递展示字段与调用ID；保留消息位置供运行记录恢复。默认历史API仍返回完整消息，模型原始历史不变。大量旧测量序列不会被重复传给页面的JSON解析器。

快照独立存入`CHAT_CHART_DB`，绑定账号、会话、工具调用及校验摘要；同一调用不可换数据覆盖。历史仅恢复当前消息中的实际工具调用；打开历史图表不重新调用MES、不重新计算控制限，也不把图表图片加入模型上下文。访问使用现有绑定账号/会话约束，并未增加一套用户登录认证。默认启用，`ENABLE_CHAT_CHARTS=False`可整体关闭；配置修改须重新加载服务。

## 验证

后端测试：`venv/Scripts/python.exe -m pytest tests/test_chat_charts.py --basetemp tmp/pytest-charts`。

JS测试：`node --test tests/chart_spec.test.cjs tests/workspace_presentation.test.cjs`。

浏览器压力检查使用真实页面、真实Worker和固定ECharts，API及数据为隔离合成夹具，不调用模型或MES。需单独安装开发工具Playwright，并有本机Chrome或Edge：

```powershell
.\venv\Scripts\python.exe -m pip install playwright
.\venv\Scripts\python.exe -X utf8 scripts/check_chat_chart_performance.py
.\venv\Scripts\python.exe -X utf8 scripts/check_chat_chart_performance.py --cpu 4
```

结果及截图保存在本地忽略目录`tmp/chat-chart-performance/`。检查100张历史图、每图两个500点面板和密集标记；输入95分位须低于50毫秒、帧间隔95分位不超过50毫秒、检测到的长任务须低于100毫秒，图像/负载保留数不超过2。输入指标为input事件到下次动画帧回调的时间，帧间隔为连续requestAnimationFrame间隔。压力段使用缓存的原生DOM目标与键盘事件，避免重复自动化定位器遍历成为被测开销。

还检查普通聊天不加载ECharts、原始数据分页、导出、慢请求、失败、跨会话晚到响应、同一事件循环内暂停/恢复的取消请求重启，以及流式文字先于图像挂载。性能数字是当前测试环境的测量，不代表对任意终端、任意数据量或现有聊天自身性能作无限保证；发现图表引入的长任务应阻止验收。

### 首轮测量（历史记录）

本机Chrome 157.0.8103.39，无头模式1440×1000，隔离合成数据；100张图卡代表历史条目，只有进入视区的图实际加载。每图两个500点面板，全部点附带合成标记以增加绘制负载。测量段包含首次可见图加载、连续输入和跨历史滚动；没有用合成数据冒充MES验收。

| 场景 | 无图输入95分位 | 有图输入95分位 | 有图帧间隔95分位 | 主线程≥50ms长任务 |
| --- | --- | --- | --- | --- |
| 普通环境 | 15.5ms | 13.5ms | 16.8ms | 0 |
| DevTools CPU降速4倍 | 13.9ms | 10.6ms | 16.9ms | 0 |

两种场景全部功能断言通过；可见负载实际保留1份、最多挂载1张图，设定上限为2。降速样本仍记录到两个约52ms的长动画帧，其阻塞时长均为0，不将长动画帧与主线程长任务混为一谈。图表失败及Worker失败时输入可用；切换会话不插入旧图；文字流完成前不挂载图表。

最终数据：本地`tmp/chat-chart-performance/results-cpu1.json`、`results-cpu4.json`；截图与导出文件同目录。前期SVG直接显示方案及未加交互安静期的降速检查出现过超标，已改为Worker生成PNG并将解析/挂载延后至交互空隙，未以先前失败的方案交付。
