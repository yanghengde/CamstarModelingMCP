# 质量高级功能开发顺序

2026-10-28开始，按可独立审阅、测试和验收的阶段推进。当前代码有50个质量工具；第一阶段受限批返工、第二阶段的受限容器数量损失准备与批报废前置检查已交付代码，其余阶段尚未实现，不能将接口发现视作功能交付。

| 阶段 | 开发内容 | 当前进度与验收要求 |
|---|---|---|
| 1 | 原生整批返工：准备、成员/原因/路径核对、确认、单次执行、未知事务检查 | 已新增[受限批返工](quality-lot-rework.md)；代码和模拟回归完成，真实批、数量影响、部署覆盖及最终历史仍待验收 |
| 2 | 批报废及数量处置 | 进行中。已新增[数量损失准备与批报废前置检查](quality-quantity-loss.md)：单个基础Container的原生LossDetails部分/全量损失计划、旧损失入口阻断；多成员抽样批因未实现注释、原因类型冲突及部署效果未核实，结果3仍阻断，不循环扣量模拟整批事务。真实扣量/关闭/生产数量及历史待验收 |
| 3 | 检验失败转全检、自动扣量及相关处理 | 核实MES原生触发机制、任务重算、计数样本与拒收量的区别、原因配置、移站/事件连带影响；防止客户端和MES各扣一次 |
| 4 | SPC计算、判异、违例及注释写入 | 先明确控制图类型、分组/顺序、中心线/控制限来源、规则及版本，再提供可复核计算；写入须绑定原始数据与配置，不能把规格限代作控制限或据SPC自动放行 |
| 5 | 通用质量事件流程 | 在现有NCR升级和CAPA范围之上，核实类别、流程模板、组织允许动作、分派及状态转换，再封装独立准备工具；保留处置原码 |
| 6 | 复杂审批与电子签名 | 核实审批表/顺序、角色权限、退回/撤回及签名上下文；设计受控签名输入，不在工具日志、计划或模型对话中持久保存口令；确认操作不能代替电子签名 |

每阶段均需提供真实API/元数据依据、明确参数、准备预览、工具路由说明、失败与状态变化测试、事务防重和文档。真实业务提交须有明确目标并审阅对应计划；本次仅开发代码和只读联调，没有MES业务写入或服务重启。

复用现有统一质量事务：`prepare_* → 展示计划 → execute_quality_transaction确认单次提交 → unknown保留占用 → inspect只读证据 → 最终审计证据人工review`。没有经核实的历史关联时，不提前宣称自动成功，不通过清库或换工具重试未知事务。

这份计划规定开发顺序，不是对各部署高级模块可用性、工期或业务验收完成的承诺。
