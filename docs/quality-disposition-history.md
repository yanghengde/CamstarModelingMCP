# C7 质量事务归因与审计

对提交后状态仍为 `unknown` 或 `in_flight` 的质量计划，先调用 `reconcile_quality_execution(plan_id, plan_digest)`。核对是只读的，工具根据原计划类型返回可验证的历史或下一步取证入口。

| 原计划 | 历史核对 | 结案条件 |
| --- | --- | --- |
| 单容器损失、整批报废、整批返工 | `native_history_match` 表示父子事务及原生效果已与原请求匹配。 | 复读原生历史和当前原对象效果，经确认可用 `resolve_history` 结案。 |
| 整批 OK | `native_request_match` 表示父记录匹配原批、完成标志和结果 1。 | 成员最终影响须用服务端证据人工审核。 |
| 普通检验、批采样 | 带系统标记的计划自动查找主历史，核对原容器、测试、批、样本和可见点值。旧计划须指定候选。计数累计值及未持久化选项仍需独立查证。 | 人工核实提交效果。 |
| 批维护 | 可定位同一批的唯一原评论候选。历史中的数量和频率可比对，保留选项及任务重算仍需现场证据。 | 人工核实提交效果。 |
| 审批、签名、事件、SPC、建模及其他质量事务 | `manual_review_required` 返回 `inspect_quality_transaction`，该入口读取原对象及已支持的专用证据。 | 通过 `review_quality_transaction(action=resolve)` 登记人工最终服务端证据。 |

工具先核对计划摘要、部署环境、固定执行载荷和本地尝试记录。对损失、整批处置及带系统标记的普通检验，工具按完整系统标记查找唯一主历史，核对原生服务、有效状态和本次已结束的提交时间窗口。MES 使用 GMT 时间，与本地尝试开始、结束各保留 5 秒容差。指定候选事务 ID 时仍核查标记唯一性。无记录、冲销、重复候选、时窗或字段不符均保留待审状态。

单容器损失核对主历史的原容器、工艺及变更计数，并将前后余额与原计划比较。数量汇总和损失明细必须同属该事务，且损失增量、主单位和第二单位、原因、关闭状态、生产数量选项均匹配。整批报废还要求父历史明确对应原批、结果 3 和报废原因，子事务完整覆盖原计划成员。工具复读主历史和全部有界明细，拒绝变化或多出的明细。

整批返工要求父历史指向原批、记录结果 2 和原返工原因。每个原成员必须恰好有一条有效 `Rework` 主历史和一条由它关联的 `MoveHistory`。逐成员核对返工前的容器版本、源步骤、路径、目标步骤和工序、返回及结束步骤。支持原计划主数量保留、第二数量为零的返工，要求成员历史无失败或关闭，且同一事务内无数量调整记录。

## 本地结案

对历史匹配的单容器损失、整批报废或返工，使用 `review_quality_transaction`，传入原计划 ID 与摘要、`action=resolve_history`、`conclusion=committed`、作为 `evidence_reference` 的原生事务 ID，以及核对说明。经确认后，工具先复读原生历史，再独立读取原容器余额和状态，或原批结果、成员去向与原采样任务清理情况。原任务基线缺失、原对象当前状态不一致、出现新任务或复读变化时，原计划保持待审。已中断的 `in_flight` 需先用 `recover` 恢复到 `unknown`。

全部检查通过后，本地事务把原计划更新为 `history_committed` 并同时保存审计。审计记录包含原响应、原尝试、事务 ID、计划摘要、历史及当前证据摘要。状态变更只解除这份日志中的待审占用。原计划为单次提交，仍不可重放。人工结案与历史结案使用各自的状态和证据记录。

## 验证范围

以只读方式复核 C4 两成员返工 `400000000000fe20`、两成员报废 `400000000000fe22`、双单位部分扣量 `400000000000fe23` 和单单位全量关闭 `400000000000fe24`。四笔均通过原生历史和当前效果核对，并在隔离本地日志演练历史结案。批采样 `400000000000fe18` 已核实汇总、样本和点值的父键关系，返回请求已关联、效果部分匹配。C4 使用独立验收日志，本次为回放构造了本地尝试时间窗。

现场未查到结果 1 的整批 OK、批维护或单容器检验历史，也未查到事件更新、签批和 SPC 注释样本。审批、事件、签名、SPC 与建模等事务的自动归因需要各自完整的原生字段及现场证据，目前可走人工审计闭环。只读回放和样本可用性记录位于本地 `docs/quality-fixtures/c7-closeout-live-readonly.json` 和 `docs/quality-fixtures/c7-closeout-history-availability.json`。

675 项定向离线测试通过。全项目 4562 项测试及 2 项子测试通过，真实 HTTPX 传输尝试为 0。测试覆盖原提交时窗、候选歧义、错误批、冲销、证据变化、原对象不符、任务清理未完成和本地审计写入失败时的回滚。
