# C7 数量处置历史归因

单容器 `ChangeQty` 损失和原生 `ExecuteSamplingLot` 整批报废现在可通过 `reconcile_quality_execution(plan_id, plan_digest)` 自动定位并核对历史。也可以指定 `candidate_txn_id`，工具仍核查原评论在完整历史中的唯一性，指定候选不会跳过重复检查。

工具先核对原计划摘要、部署环境、固定执行载荷和本地尝试记录。随后按系统生成的完整事务标记查找唯一主历史，核对原生服务、有效状态和本次已结束的提交时间窗口。时间比较使用 MES 的 GMT 时间，与本地尝试的开始、结束时间各保留 5 秒容差。时间未返回、超过窗口或原提交未结束时，历史无法完成自动归因。

单容器损失核对主历史的原容器、工艺及变更计数，并将前后余额与原计划比较。数量汇总和损失明细必须同属该事务，且损失增量、主单位和第二单位、原因、关闭状态、生产数量选项均匹配。整批报废还要求父历史明确对应原批、结果 3 和报废原因，子事务完整覆盖原计划成员。工具复读主历史和全部有界明细，拒绝变化或多出的明细。

`native_history_match` 表示已将记录的扣量和关闭效果关联到原提交。原计划仍保留 `unknown` 状态，需通过 `review_quality_transaction` 人工审核。当前库存可能受后续事务影响，抽样任务清理也需从原成员和原任务基线独立核对。无历史、冲销、候选歧义或字段冲突都不会给出已关联结论。

本轮以只读方式复核 C4 已执行的三笔事务。双单位扣量 `400000000000fe23`、单单位全量关闭 `400000000000fe24` 和两成员报废 `400000000000fe22` 均通过原生字段比对。C4 使用独立验收日志，现场复核用合成尝试时间窗检查历史映射。真实本地尝试记录、错误时间窗、重复候选、缺失成员、冲销和复读变化由离线测试覆盖。本轮未重新提交这些事务。
