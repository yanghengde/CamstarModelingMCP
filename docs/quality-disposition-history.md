# C7 质量处置历史归因

单容器 `ChangeQty` 损失和原生 `ExecuteSamplingLot` 整批报废、返工均可通过 `reconcile_quality_execution(plan_id, plan_digest)` 自动定位并核对历史。也可以指定 `candidate_txn_id`，工具仍核查原评论在完整历史中的唯一性。

工具先核对原计划摘要、部署环境、固定执行载荷和本地尝试记录。随后按系统生成的完整事务标记查找唯一主历史，核对原生服务、有效状态和本次已结束的提交时间窗口。时间比较使用 MES 的 GMT 时间，与本地尝试的开始、结束时间各保留 5 秒容差。时间未返回、超过窗口或原提交未结束时，历史无法完成自动归因。

单容器损失核对主历史的原容器、工艺及变更计数，并将前后余额与原计划比较。数量汇总和损失明细必须同属该事务，且损失增量、主单位和第二单位、原因、关闭状态、生产数量选项均匹配。整批报废还要求父历史明确对应原批、结果 3 和报废原因，子事务完整覆盖原计划成员。工具复读主历史和全部有界明细，拒绝变化或多出的明细。

整批返工要求父历史指向原批、记录结果 2 和原返工原因。每个原成员必须恰好有一条有效 `Rework` 主历史和一条由它关联的 `MoveHistory`。逐成员核对返工前的容器版本、源步骤、路径、目标步骤和工序、返回及结束步骤。支持原计划主数量保留、第二数量为零的返工，要求成员历史无失败或关闭，且同一事务内无数量调整记录。

`native_history_match` 表示已将历史中记录的扣量、关闭或返工路径效果关联到原提交。原计划仍保留 `unknown` 状态，需通过 `review_quality_transaction` 人工审核。当前成员状态可能受后续事务影响，抽样任务清理也需从原成员和原任务基线独立核对。无历史、冲销、候选歧义或字段冲突都不会给出已关联结论。

此前以只读方式复核了 C4 双单位扣量 `400000000000fe23`、单单位全量关闭 `400000000000fe24` 和两成员报废 `400000000000fe22`。本轮复核两成员返工 `400000000000fe20`，父记录、两条移动路径和数量均匹配。C4 使用独立验收日志，现场复核用合成尝试时间窗检查历史映射。本地尝试记录、错误时间窗、重复候选、缺失成员、冲销和复读变化由离线测试覆盖。

566 项相关回归通过，全项目 4538 项测试及 2 项子测试通过，离线测试中真实 HTTPX 传输尝试为 0。返工专项覆盖成员和移动记录缺失、去向或原因冲突、冲销、数量调整及两次读取不一致。现场只读证据位于本地 `docs/quality-fixtures/c7-disposition-live-readonly.json` 和 `docs/quality-fixtures/c7-rework-live-readonly.json`。
