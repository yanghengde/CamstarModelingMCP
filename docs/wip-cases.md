# 在制品异常交接与经验审核

在现有 LangGraph 聊天中发送 `在制品 异常演示`，可查看一次完整的白班到夜班交接。演示使用临时样例库。实际使用时，命令中的单号取自本服务返回的交班记录编号。

| 现场动作 | 聊天示例 |
|---|---|
| 核实容器并登记 | `在制品 登记 BOX001 老化测试疑似超时` |
| 将已有交班备注转为异常单 | `在制品 立单 1` |
| 接手与追加进展 | `在制品 接单 1 白班小李`、`在制品 跟进 1 已调取设备记录` |
| 交给下一班 | `在制品 转交 1 夜班小周` |
| 下一班查看未结事项和原始记录 | `在制品 待办`、`在制品 详情 1` |
| 核实后结案 | `在制品 结案 1 已对照工艺卡 A 版与设备记录 R27，加工时间正常` |
| 提交候选经验 | `在制品 提炼 1 老化测试应分别核对排队时长和设备加工时长` |
| 查阅本环境有效的已审核经验 | `在制品 经验` |

异常单和原始备注使用同一个编号。记录中分别显示聊天账号和手工填写的负责人，时间为 UTC。结案结果由经办人填写；MES 的挂起、放行和过站状态以现场系统为准。

## 审核结案经验

审核人员在应用使用的环境和经验数据库中运行现有管理命令。先核对候选的来源单号、结案证据、适用工艺和版本，再将下列示例中的 7 替换为实际经验编号。

```powershell
python -m agent.learning list --state candidate
python -m agent.learning review 7 --action activate --evidence "已核对工艺卡 A 版与设备记录 R27" --ttl-days 90
python -m agent.learning history 7
```

评审不通过时使用 `--action reject` 并填写理由。已发布经验失效时使用 `--action retract`。聊天中的「在制品 经验」按当前部署环境、契约版本和有效期读取最近的已审核记录；工艺版本的适用性由审核人核实。
