# 多层追溯与未知写入结果处理

新增只读工具 `get_container_genealogy`。从明确的父子、拆分和合并关系进行广度优先遍历；按容器 ID 去重并保存证据，保留每个容器的返工记录。共享节点只读取一次。报告有向环，但不同时间的历史关系可能合法成环，不代表当前配置错误。

默认深度 2、最多 10 个节点、每个分段 2 页。允许深度 0..3、节点 1..20、分段页数 1..3；每页 20 条，整体 90 秒和 200k 字符预算。超出预算、分页未完、身份无法解析或接口失败都会返回 boundaries/failures。不递归未知 CrossRefType 的 HistoryId/TrackingId，避免把其他实体错误解释为容器。

traversal_complete 只表示明确关系在请求预算内已遍历完；complete 始终为 false，不承诺覆盖全部跨容器历史或解码所有交叉引用。完整的复合追溯和生产完成口径仍不能由这个标志推导。

修复批量导入日志：网络超时、连接异常、HTTP 500/502/503/504 的写入结果记为 success=null，表示服务端可能已经执行。操作停止、计划不自动重放，需对照现场核对；不再把通信失败当作确认未执行。

验证：123 项相关测试、2 项子测试通过；新增覆盖多节点循环/去重、深度和页数边界、分页耗尽、未知交叉引用不遍历，以及写超时结果未知。BOX-0001 连续三次实际读取成功，耗时 0.803/0.324/0.248 秒，各返回一个节点和零条可展开关系。此样本不足以完成非空多层关系现场验收，测试数据链为模拟响应。证据见 genealogy-validation.json。
